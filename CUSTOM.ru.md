# Свои проверки и исправления

Аптечку можно собрать со своими проверками и исправлениями — для того, что есть только у тебя: свой роутер, свой NAS, своя схема VPN. Они живут в папке `custom/` рядом с `engine/`. Эта папка в `.gitignore`: она остаётся на твоём компьютере и не попадает в репозиторий.

Твои проверки выглядят как встроенные без лишней работы: строка в таблице со значком, цветом и подсказкой, пункт на вкладке **Показатели** (там её можно выключить), кнопки действий, и кот говорит об их бедах в облачке. Твои исправления проходят тот же контроль, что и встроенные: проверка параметра, окно подтверждения, команда «как сделать руками» и пробный режим `DRY_RUN=1`.

Для этого программу нужно собрать из исходников. Шаги ниже — с нуля.

## 1. Поставить инструменты

- **Rust** 1.89 или новее — с сайта [rustup.rs](https://rustup.rs). На Linux и macOS это одна команда в терминале, на Windows — установщик.
- **Git** — чтобы скачать исходники.
- На **Windows** — средства сборки C++, которые предложит установщик Rust. На **macOS** — `xcode-select --install`.

Проверить:

```sh
cargo --version
```

## 2. Скачать и один раз собрать

```sh
git clone https://github.com/UlyanaPerova/first-aid-cat
cd first-aid-cat/engine
cargo build --release
```

Первая сборка идёт несколько минут. Программа — `engine/target/release/aptechka` (`aptechka.exe` на Windows). Запусти её, чтобы убедиться, что всё работает.

## 3. Начать с примера

В репозитории есть рабочий пример — `examples/custom/mod.rs`. Он сравнивает сайт твоей страны с двумя зарубежными и говорит, когда не открываются только зарубежные (частый признак сломанного VPN на роутере), и у него одно исправление — открыть страницу роутера.

Из корня репозитория:

```sh
cp -r examples/custom custom
cd engine
cargo build --release
```

Всё. `build.rs` замечает `custom/mod.rs` и собирает его в программу. Запусти: на вкладке **Сеть** появилась строка «Local and foreign sites», на вкладке **Показатели** — она же в списке. Удалишь папку `custom/` и соберёшь снова — получишь обычную программу.

Надписи твоих проверок показываются как написаны (их не переводят): пиши на том языке, на котором читаешь.

## 4. Добавить проверку

Проверка — функция, которая возвращает строки. Добавь её в список в `units()`:

```rust
Unit {
    id: "my_nas",                 // свой код, начинается с my_ (по нему «Показатели» запоминают выключенное)
    cat: Cat::Net,                // вкладка: Net, Ai, Gpu, Dev, Look, Sys
    title: "Мой NAS",
    about: "Свои: отвечает ли NAS",
    run: check_nas,
    default_on: true,
},
```

и напиши саму функцию:

```rust
fn check_nas() -> Vec<Check> {
    let open = std::net::TcpStream::connect_timeout(
        &"192.168.1.10:445".parse().unwrap(),
        std::time::Duration::from_secs(3),
    )
    .is_ok();
    if open {
        vec![Check::new("net", "Мой NAS", OK, "отвечает")]
    } else {
        vec![Check::new("net", "Мой NAS", BAD, "не отвечает")
            .hint("Включён ли он? На месте ли кабель?")
            .fixes(vec![fx("my_wake_nas", "Разбудить", None)])]
    }
}
```

Статусы: `OK`, `WARN` (внимание), `BAD` (беда), `INFO` (для сведения). Первый параметр `Check::new` — вкладка: `"net"`, `"ai"`, `"gpu"`, `"dev"`, `"theme"`, `"sys"`.

Несколько правил, чтобы проверка не врала:

- Не узнала — не пиши «в порядке». `INFO` с `.unknown()` и подсказкой «не проверить».
- У каждого запроса в сеть — тайм-аут. `crate::diag::http_get_ms(адрес, тайм-аут_с, предел_байт, None)` делает это сам и возвращает код ответа и время.
- Внешние программы — только через `crate::cmd::exec`: тайм-ауты, ограничение вывода, чистое окружение.
- Проверка запускается раз в несколько минут. Не качай в ней большие файлы — или запоминай последний результат и замеряй редко (например, не чаще раза в 30 минут).

## 5. Добавить исправление

Код исправления начинается с `my_`. Ты пишешь пять маленьких функций, программа вызывает их по порядку, когда нажимают кнопку:

| Функция | Что делает |
|---|---|
| `valid(id, arg)` | Разрешены ли такой код и параметр. Всё остальное — отказ. |
| `confirm(id)` | Текст окна подтверждения для исправлений с последствиями, или `None`. |
| `what(id)` | Одна фраза: что произойдёт. |
| `manual(id, arg)` | Команда, чтобы сделать то же руками; её покажут человеку. |
| `apply(id, arg)` | Делает исправление. Возвращает `(успех, сообщение)`. С `DRY_RUN=1` — только описывает, что сделала бы. |

Пример всех пяти — `my_open_router` в `examples/custom/mod.rs`.

### Кнопки у спокойных строк и список действий

Кнопка исправления обычно видна только у красных и жёлтых строк. У спокойной строки (зелёной или синей) кнопка тоже появится, если код исправления начинается с `my_`: так делаются действия «по просьбе» — что-то выключить, что-то запустить.

Чтобы дать в одной строке несколько действий, первым поставьте заголовок: `fx("menu", "Скорость", None)`, а за ним настоящие исправления. В строке будет одна кнопка «Скорость ▾», по нажатию откроется список остальных:

```rust
.fixes(vec![
    fx("menu", "Скорость", None),
    fx("my_fans", "Тихо", Some("100")),
    fx("my_fans", "Максимум", Some("255")),
])
```

Каждый аргумент, переданный так, должен принимать ваш `valid()`.

## 6. Пусть напишет ИИ-агент

Если у тебя есть Claude Code, Codex или другой агент для кода — открой его в папке репозитория и дай такой запрос, вставив свою проблему в середину:

> Прочитай CUSTOM.ru.md и examples/custom/mod.rs. В папке custom/ (если её нет — создай из примера) добавь проверку для такой проблемы: **[что ломается, как ты это замечаешь и что помогает]**. Соблюдай правила из CUSTOM.ru.md: честные статусы, тайм-ауты, внешние команды только через crate::cmd, коды исправлений с my_ и функциями valid, confirm, what, manual и apply, поддержка DRY_RUN. Потом запусти `cargo build --release` и `cargo test --release` в engine/ и исправь ошибки.

Собери и сначала попробуй исправление в пробном режиме:

```sh
DRY_RUN=1 engine/target/release/aptechka --fix my_wake_nas
```

## Перевод

У интерфейса два языка. Тексты своих проверок пишите на том языке, которым пользуетесь: они показываются как написаны. Если они по-русски, а в английском интерфейсе нужны по-английски, положите перевод рядом с кодом — в `custom/en.txt`, в том же формате, что `engine/i18n/en/*.txt`:

```text
ru: Мой NAS
en: My NAS

ru: не отвечает уже {} мин
en: no answer for {} min
```

Из корня репозитория `python3 tools/i18n.py missing custom` печатает ваши строки без перевода в готовом для вставки виде, а `python3 tools/i18n.py check` считает их.

## Обновления

Папка `custom/` переживает `git pull`. После обновления собери заново. Если программа поменяла то, чем пользуется твой код, компилятор покажет, где именно.
